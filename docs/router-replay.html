What happened before this historical replay?

Batch normalization is folded into the pretrained model. Activation ranges are calibrated once and frozen. In this recorded pilot, each of 54 operators had five choices: W4A8, W4A16, W8A8, W8A16 and FP32. Fisher profiling estimated loss sensitivity for each joint weight/activation choice. All MILP budget solves finished first, minimizing summed Fisher scores under storage and a shared BitOps cap; then every unique seed was measured. Current runs exclude FP32 from the choices and have no compute cap unless requested. A16 is integer activation quantization.

How does local exploration work?

The router cycles through budgets and proposes feasible one-operator changes or two-operator exchanges. Within each budget it alternates preference between edits that change weight precision and edits that change only activation precision, falling back to the other type when needed. Within the preferred type, smaller Fisher-score changes are tested first. The actual search measurement decides whether an edit succeeds.

What exactly gets transferred?

An edit records operator IDs and exact before/after formats, such as “classifier W8A16 → W8A8.” The destination must have the same starting format on every edited operator. All other operators retain the destination’s choices. In this historical pilot, the candidate had to fit both resource caps and be absent from the global evaluation cache. Current runs always check storage and check a compute ceiling only if explicitly configured. A failed transfer stays a contextual result; it does not erase the edit or change the Fisher scores.

What counts as success, and when can evaluation stop early?

Fewer search-set mistakes wins. With equal mistakes, lower teacher KL wins. Only a fully evaluated policy can update incumbents or create a successful-edit record. For early rejection, find every budget the candidate fits and take the largest incumbent error count. Stop only when accumulated candidate mistakes exceed that count. Equality must finish so KL can break the tie. Each unique candidate, including an early rejection, consumes one evaluation slot.

Where does the Pareto frontier enter?

The replay above shows search-split measurements, not final validation accuracy. In the current code, search ends at its allowance or when no feasible untested proposal remains. The union of the storage search frontier, BitOps search frontier and MILP seeds is deduplicated and frozen. Every selected policy and FP32 then runs on every test-manifest image, without early rejection: 50,000 per model for a full ImageNet validation split. The current outputs are frontier.csv, accuracy versus compression in frontier.png, and accuracy versus GigaBitOps in frontier_bitops.png (also SVG). FP32 is a baseline outside both quantized frontiers. The router adds no inference component or trained routing network.

What did this particular pilot show?

This is a recorded CPU pilot: 54 operators, eight budgets, 24 unique candidates, 100 search images and 500 held-out images from 10 selected ImageNet classes, and a compute cap of 75% of all-W8A8 BitOps. There were two transfer evaluations. Against a transfer-disabled run with the same allowance, the held-out policies and predictions were identical. This replay explains the mechanism; it does not demonstrate a router speedup or accuracy gain. The live CLI defaults to 64 evaluations, and its final held-out evaluation is separate from the search measurements shown here.
